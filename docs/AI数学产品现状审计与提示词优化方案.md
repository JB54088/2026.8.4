# AI 数学产品现状审计与提示词优化方案

> 适用仓库：`ai-math-coach-product`  
> 审计依据：当前代码、当前页面路由、接口实现和 `c24fcb8` 工作区状态。  
> 原则：复用已有能力，优先修复真实断点；演示数据、真实识别和待确认结果必须明确区分。

## 1. 当前产品整体评价

当前产品已经具备“章节题库 → 作答 → 整卷提交 → 逐题分析 → 错题/训练/复测”的骨架，不是空壳 Demo。后端 `/api/submissions` 会为一整份题目生成一个 `submissionId`，逐题保存答案、手写图、轨迹、用时和识别结果；报告也已经有题型、章节、知识点、错误类型、能力诊断和学习任务字段。

当前最准确的产品判断是：**数据闭环的骨架已形成，AI 教学闭环还没有稳定落地。** 主要问题不在于再增加页面，而在于同一能力被多个页面重复表达，AI 把多个高风险任务塞进一次调用，识别失败时又容易被启发式原因误认为学生错误。

已确认的能力：

| 能力 | 现状 | 判断 |
|---|---|---|
| 数学一/二/三选择 | `/math-type` 持久化选择，课程、章节、题目按 `student.mathType` 过滤 | 已可用，保留 |
| 章节学习 | `/chapters` 展示章节题量、完成数和正确率 | 已可用，入口需要更聚焦 |
| 选择题作答 | 选项点击保存 `selectedOption`，不再显示手写画布 | 已修复，保留 |
| 填空题/主观题 | 使用做题空间保存笔迹、图片和轨迹 | 已可用，识别依赖真实 AI |
| 整卷提交 | `/api/submissions` 统一锁定整卷并逐题处理，单题异常不阻断其他题 | 核心能力，P0 保留 |
| 手写识别 | `callAiScratchRecognition` 调用视觉模型 | 有真实调用骨架，但提示词与失败状态需重构 |
| 整卷报告 | `buildSubmissionReport` 有总分、错误统计、能力、知识点和任务 | 数据较全，页面需分层 |
| 逐题过程诊断 | 有 `structuredSteps`、首个错误步骤、步骤对照 | 有字段，但低置信和无证据时仍可能被误判 |
| 相似题/20 题训练 | 后端按 10/20 题组成，训练工厂有校验 | 能运行，但题目来源、答案可信度和主观题判分需加强 |
| 原题重做/掌握验证 | 已有路由和接口 | 已有闭环入口，但验证状态更新不完整 |
| 静态演示 | `public/static-api.js` 明确标记 `static-demo`，不做真实 OCR | 可以保留，但不能让用户误以为是真实 AI |

建议产品定位保持为：**面向考研数学一/二/三的“过程诊断型题库”，核心价值是识别学生第一次出错的位置，并把错误转化为下一步可验证的训练。**

## 2. 当前最需要解决的五个问题

### 2.1 AI 单体提示词承担过多任务

`server.js:554-636` 的 `callAiScratchRecognition` 同时做图片识别、最终答案提取、步骤判断、首错定位、根因诊断、薄弱点和训练建议。任务边界过大，任何一个识别错误都会污染判分、错题本和推荐题。

**处理：**拆成“识别 → 范围/知识点 → 确定性判分 → 过程诊断 → 教学反馈 → 训练生成”六个模块。第一步不接收标准答案，避免答案锚定。

### 2.2 没有可靠的低置信度确认门

当前虽然保存 `recognitionConfidence` 和 `uncertainRegions`，但没有统一规则：低置信度时不能计错、不能直接生成薄弱点，也没有要求学生确认识别结果。

**处理：**置信度小于 70、存在不确定区域、公式无法解析或题目条件不足时，状态统一为 `needs_confirmation`；不计入错误统计，不更新掌握度，前端提供“确认识别结果/重新书写”。

### 2.3 无识别证据时会回退到题目预设原因

`reasonForAttempt` 和 `diagnose` 会在学生答案为空或识别待定时使用 `question.reason` 等题目字段。这会把“系统没看清”变成“学生方法错误”，污染错题本和能力画像。

**处理：**把 `unanswered`、`pending_recognition`、`recognition_error`、`graded_wrong`、`process_issue` 分成互斥状态。没有学生有效答案或步骤时，只能输出“待确认/未作答”，不能输出学生错因。

### 2.4 报告页信息齐全，但阅读层级仍像后台诊断台

`public/app.js:966-1042` 直接展示批改状态码、错误统计、能力诊断、训练任务和逐题入口；`questionReview` 又把 OCR 置信度、错误层级、批改状态等技术字段与学生结论混排。

**处理：**报告只保留三层：第一层“这次考得怎样”；第二层“哪几题、哪一步错”；第三层“下一步做什么”。技术状态和 OCR 字段折叠到“识别详情”。

### 2.5 训练题的“有题”与“题目可信”还不是同一件事

`server.js:1784-1842` 确实按 10/20 题生成并校验，但生成依赖 `public/training-factory.js` 的规则化题目工厂；`buildRetestFromBatch` 仍会用种子题答案拼出重做题。主观训练题 `gradeTrainingQuestion` 返回 `null`，不能形成真实的过程批改闭环。

**处理：**训练题必须保存 `sourceEvidence`、`solutionVersion`、`validatedBy` 和校验结果；主观题走与整卷相同的识别/诊断管线；原题重做直接引用原题快照，不用新题的答案冒充原题标准答案。

## 4. 已有功能优化清单

### 4.1 `/math-type` 数学类型选择

- **问题：**已有选择和持久化，但登录页和数学类型页存在两处选择，用户可能不清楚哪次选择生效。
- **保留/合并/拆分：**保留一个正式选择页；登录页只提供“进入系统”，已有选择用户直接进入课程首页。
- **名称和入口：**“考试数学类型”改为“请选择你的考研数学类型”；设置页使用“切换考试类型”。
- **AI：**不调用 AI，必须由后端/题库规则过滤。
- **流程：**登录 → 选择数学类型 → 保存 `student.mathType` → 拉取受限章节 → 进入课程首页。
- **优先级：**P0。
- **验收：**数学一/二/三分别拉取正确章节；直接访问 `/chapters` 也不能绕过过滤。

### 4.2 `/chapters` 章节学习

- **问题：**当前页面同时暴露题量、难度、题源和训练模式，章节选择被配置项干扰。
- **保留/合并/拆分：**章节卡片保留；题量、难度、题源放入“本轮设置”抽屉，默认使用推荐值。
- **名称和入口：**“开始做题/继续学习”保留；“模式”文案改为“训练阶段”。
- **AI：**只在已有诊断结果后参与推荐，不参与章节过滤。
- **流程：**选择章节 → 默认推荐训练阶段 → 进入做题 → 提交后回到报告。
- **优先级：**P1。
- **验收：**第一次用户无需理解 `sourceType`、`difficulty` 即可开始；手动修改后请求仍按数学类型和章节过滤。

### 4.3 `/practice` 做题页

- **问题：**选择题、填空题、主观题已有不同答题方式，但题目上下文仍可能暴露知识点标签；提交语义必须始终是“提交整卷”。
- **保留/合并/拆分：**选择题保留选项；填空和主观题统一使用做题空间；上一题/下一题只负责保存和切换，整卷提交单独确认。
- **名称和入口：**删除“刷题面板/草稿”字样，统一叫“做题空间”；“提交答卷”明确为整卷。
- **AI：**答题中不调用识别，不展示答案和诊断；提交后统一进入批改。
- **流程：**题目 → 选择或手写 → 自动保存 → 下一题 → 提交整卷 → 批改状态 → 报告。
- **优先级：**P0。
- **验收：**选择题没有画布；填空/主观题没有普通答案输入框；刷新后笔迹和当前题目恢复。

### 4.4 `/api/submissions` 整卷提交

- **问题：**核心数据结构已具备，但缺少明确的状态机和“识别待确认不计错”规则。
- **保留/合并/拆分：**保留为唯一批改编排器；单题 `/api/attempts` 只用于非整卷快速保存或内部复核，不能生成另一套诊断结果。
- **接口调整：**补充 `submission.status`、`questionProcessing.status`、`evidenceVersion`、`needsConfirmation` 和 `gradingVersion`。
- **AI：**每题按题型分流：选择题不用手写 AI；填空/主观题识别后再判分和诊断。
- **流程：**完整性检查 → 锁定 → 识别 → 判分 → 错题深诊断 → 生成报告；局部失败记录失败原因并继续。
- **优先级：**P0。
- **验收：**一个 `submissionId` 关联所有题；识别失败题状态为 `needs_confirmation`，不计入错误统计。

### 4.5 `/paper-report` 整卷报告

- **问题：**已有内容很全，但状态码、错误类型和能力卡片同时展开，学生不容易找到行动入口。
- **保留/合并/拆分：**保留三层报告；批改过程折叠到“识别与批改详情”。
- **页面结构：**顶部成绩结论 → 三个最重要问题 → 错题列表 → 优先复习知识点 → 开始专项训练/原题重做；题型和能力作为可展开区域。
- **AI：**AI 只能输出证据支持的结论；低置信度显示“需要确认”，不输出确定错因。
- **优先级：**P0。
- **验收：**用户不用阅读技术状态即可知道“错在哪里、先做什么”；正确题显示轻记录，错误题显示深诊断入口。

### 4.6 `/question-review` 逐题解析

- **问题：**已有步骤对照，但 `OCR 置信度`、`gradingStatus`、错误层级与学生语言混排；标准答案可见时机需要受控。
- **保留/合并/拆分：**保留为错误题深诊断页；正确题只显示简短记录，不默认展开长解析。
- **结构：**题目与得分 → 学生识别结果 → 第一个错误步骤 → 步骤对照 → 扣分依据 → 修正方法 → 进入训练。
- **AI：**学生问某一步时只返回该步骤，不重复整题；必须引用 `stepId` 和证据。
- **优先级：**P0。
- **验收：**每个结论都能追溯到学生答案、笔迹或步骤；无有效证据时显示待确认。

### 4.7 `/similar-training` 相似题训练

- **问题：**当前 10/20 题组成和校验接口已经存在，但题目工厂与重测种子答案存在可信度风险；页面仍需要从源错题展示“为什么匹配”。
- **保留/合并/拆分：**保留一个训练页；`trainingPlan` 作为入口别名，不再维护两套页面。
- **AI：**题目生成可以调用 AI，但必须经过结构化答案校验、范围校验、重复校验和教研规则校验。
- **流程：**报告选错因 → 创建 batch → 校验完成才展示 → 逐题作答 → 批改 → 复测 → 更新掌握度。
- **优先级：**P1，主观训练判分是 P0 子任务。
- **验收：**`total === questions.length`；所有题有完整题干、题型、答案、逐步解析和来源错因；主观题不返回假分数。

### 4.8 `/original-retry` 和 `/mastery-verify`

- **问题：**功能已有，但原题重做使用文本输入，且复测结果与能力画像更新的关系不够清晰。
- **保留/合并/拆分：**前端入口合并为“复测与原题重做”，后端保留不同任务类型。
- **AI：**复测按正式作答流程识别过程；不能只比较最终答案。
- **流程：**专项训练完成 → 变式复测 → 原题重做 → 通过/未通过 → 更新掌握度和推荐。
- **优先级：**P1。
- **验收：**未完成训练不能伪造“掌握”；复测通过必须至少满足同知识点新题正确且原题重做通过。

## 5. 应合并或删除的功能

1. **隐藏前台八步骤导航。** 当前 `loopProgress()` 已返回空字符串，继续保留后台 `loop` 数据，但不让学生手动切换“检测/诊断/复习/检查/训练”等内部阶段。
2. **合并 `diagnosis`、`knowledgeReview`、`understandingCheck`。** 对学生只呈现“诊断后的下一步”，内部保留状态和接口。
3. **合并 `similarTraining` 与 `trainingPlan`。** 训练题和训练计划必须是同一批次数据，避免用户进入两个看似不同的入口。
4. **合并 `originalRetry` 与 `retest` 的用户入口。** 后端任务类型可以保留，前端只显示“复测与原题重做”。
5. **删除报告页默认展开的技术字段。** `gradingStatus`、OCR 置信度、内部状态码、算法阶段名放入折叠的“识别详情”。
6. **删除无证据的错误原因回退。** 不删除后台字段，但禁止用 `question.reason` 代替学生真实错因。
7. **不删除静态演示模式。** 但所有演示报告、训练题和 AI 状态必须带“演示数据/未接入真实识别”标识。

## 6. 当前学习流程断点

| 流程环节 | 已完成 | 不完整/缺失 | 影响 |
|---|---|---|---|
| 题目输入 | 题库题目已有结构化字段 | 未确认存在面向用户的拍题/题目识别入口 | 输入范围可能只覆盖题库 |
| 识别题目 | 手写作答识别接口存在 | 当前识别提示词把判分和诊断混在一起 | OCR 错误会扩散到全链路 |
| 判断数学范围 | 学生选择和题目过滤已完成 | 识别到的外部题目还没有独立范围判定 | 可能推荐超纲内容 |
| 数学一/二/三 | `student.mathType` 过滤已完成 | AI 输出没有强制带 `mathType` 和范围状态 | 页面和 AI 结论可能不一致 |
| 章节/知识点/题型 | 题库字段和报告聚合已完成 | AI 没有独立标注模块；无证据时可能使用题目默认原因 | 训练匹配不够精确 |
| 解题思路 | 题目有 `explanation`/标准步骤字段 | 没有统一的“先提示/后完整解”模式参数 | 容易直接给答案 |
| 分步骤讲解 | `structuredSteps` 和逐题页已完成部分 | 缺少步骤 ID、依赖关系、证据引用 | 无法稳定追问某一步 |
| 单步骤追问 | 未发现独立 tutor API | 现有页面没有统一的 step follow-up 协议 | 用户追问会回到整题解释 |
| 用户解法批改 | 整卷和单题均有批改路径 | 识别失败与学生错误未完全隔离 | 错题画像有误报风险 |
| 错误原因 | 报告有 errorStats、rootCause 等字段 | `diagnose()` 会使用启发式题目原因 | 错因确定性过高 |
| 错题本 | 有 `/collection` 和 attempt/submission 数据 | 需要保存证据版本和复测状态 | 错题不可审计/不可解释 |
| 相似/变式 | 10/20 题生成、校验和批次存在 | 主观题答案和重测题来源不够可信 | 训练可能是形式闭环 |
| 掌握验证 | 有原题重做、复测页面和接口 | 通过条件、掌握度更新规则需统一 | 学生看过解析也可能被视为掌握 |
| 后续复习/计划 | 报告生成推荐任务 | 任务完成事件和掌握度更新未形成严格状态机 | 推荐不会真正随表现变化 |

最影响体验的断点是：**学生提交手写答案后，系统没有明确告诉他“这是识别不确定、答案错误，还是过程错误”，却可能直接生成确定性诊断。** 这是 P0，优先级高于增加新页面。

## 7. 建议补充的必要功能

### 7.1 识别确认队列

- **补什么断点：**识别题目 → 批改。
- **场景：**公式模糊、涂改覆盖、置信度低时。
- **页面：**整卷报告的“需要确认”列表和逐题解析。
- **最小实现：**展示识别出的最终答案和不确定区域，用户确认/修改后重新提交该题。
- **是否必须 AI：**识别需要 AI；确认本身不需要。
- **数据/接口：**`recognitionConfidence`、`uncertainRegions`、`confirmedAnswer`、`POST /api/submissions/:id/questions/:qid/confirm`。
- **难度/风险：**中；数学风险低于直接自动判错。
- **验收：**低于 70 分不进入错误统计，确认后才可判分。

### 7.2 统一 AI 教学模式接口

- **补什么断点：**解题思路 → 分步骤讲解 → 单步骤追问。
- **场景：**用户点“给提示”“解释第 2 步”“查看完整解析”。
- **页面：**逐题解析和题目结果页。
- **最小实现：**`POST /api/ai/tutor`，传 `mode`、`stepId`、学生水平和范围。
- **是否必须 AI：**是。
- **数据/接口：**题目快照、模式、用户问题、历史提示级别、`responseSchemaVersion`。
- **难度/风险：**中高；需限制超纲方法和直接泄露答案。
- **验收：**默认先给切入点；只问一步时只回答该步；完整解析才返回全解。

### 7.3 证据化错因卡

- **补什么断点：**用户解法批改 → 错因诊断 → 错题本。
- **场景：**错误题进入报告时。
- **页面：**逐题解析和错题本。
- **最小实现：**每个错因必须绑定 `evidenceStepIds`、原始识别文本和置信度。
- **是否必须 AI：**过程判断需要 AI；状态聚合不需要。
- **数据/接口：**`errorType`、`rootCause`、`evidence`、`needsConfirmation`、`diagnosisVersion`。
- **难度/风险：**中高；误诊会影响后续训练。
- **验收：**任何确定错因都至少有一个可回看的证据步骤，否则标为“可能原因”。

### 7.4 训练题答案可信度流水线

- **补什么断点：**相似题生成 → 掌握验证。
- **场景：**生成 10 题专项或 20 题综合训练时。
- **页面：**不新增页面，训练批次创建接口完成校验后才返回。
- **最小实现：**规范化公式、独立答案复算、题干条件检查、重复度检查、数学类型范围检查。
- **是否必须 AI：**可 AI 生成，但答案校验必须是独立规则/第二次求解。
- **数据/接口：**`validation.status`、`validation.reasons`、`solutionVersion`、`sourceErrorEvidence`。
- **难度/风险：**高；数学准确率是主要风险。
- **验收：**任何校验失败题不进入 `questions` 数组；批次不能只返回 `total`。

### 7.5 任务状态机和掌握更新事件

- **补什么断点：**训练 → 复测 → 更新学习计划。
- **场景：**用户完成训练、复测或原题重做后。
- **页面：**课程首页下一步建议、报告。
- **最小实现：**任务状态 `pending/doing/completed/failed`，掌握度只由复测事件更新。
- **是否必须 AI：**不必须，AI 只生成建议文本。
- **数据/接口：**`learningTasks`、`masteryEvents`、`POST /api/tasks/:id/complete`。
- **难度/风险：**中；数学风险低。
- **验收：**看过解析不会自动完成任务；复测通过才改变知识点状态。

### 7.6 用户可见的真实/演示状态

- **补什么断点：**静态演示与真实 AI 能力边界。
- **场景：**GitHub Pages 无后端或 OpenAI 未配置时。
- **页面：**登录、报告、识别详情。
- **最小实现：**所有演示数据带 `environment: static-demo`，真实识别带 `engine`，失败显示明确状态。
- **是否必须 AI：**不必须。
- **数据/接口：**`/api/health`、bootstrap `aiStatus`、`gradingStatus`。
- **难度/风险：**低。
- **验收：**静态演示不出现“AI 已判断”“已识别步骤”等虚假表述。

## 8. 暂时不建议增加的功能

1. 社区、排行榜、打卡、勋章和社交分享：不补当前“诊断不可信”的核心断点。
2. 语音讲题和虚拟老师形象：考研数学当前最关键是公式、步骤和判分证据。
3. 大规模视频课程中心：会把产品变成课程平台，分散题目诊断闭环。
4. 复杂的家长/机构后台：十名同学演示阶段先完成学生侧准确率和可追溯性。
5. 无来源的全网自动爬题：版权、题目质量和答案校验风险高；先用可授权且可审核的数据。
6. 把所有历史题目一次性用 AI 重写：先建立题目快照、来源和质量状态，再按高频知识点增量处理。
7. 通过更多指标制造“个性化”：没有可靠证据前，不增加复杂雷达图和预测分数。

统一状态文案：

- 加载：`正在读取本次答卷，先完成其他题目的处理。`
- 识别中：`正在识别手写步骤，不确定内容不会直接计为错误。`

## 11. AI 回答逻辑修改建议

### 11.1 证据优先级

1. 学生原始笔迹图片和轨迹。
2. OCR 归一化公式与步骤。
3. 学生最终答案/选项。
4. 题目条件、定义域、参数范围。
5. 已审核标准答案和标准步骤。
6. 历史表现只用于判断是否重复，不得用来替代本题证据。

### 11.2 不同模式的输出策略

| 模式 | 默认输出 | 不能做什么 |
|---|---|---|
| `recognize` | 识别答案、步骤、置信度、不确定区域 | 不判学生对错，不给解析 |
| `grade` | 最终答案、步骤逐项判断、得分依据 | 不在无证据时猜错因 |
| `hint` | 一个切入点或下一步提示 | 不直接给最终答案 |
| `step_follow_up` | 只解释用户指定步骤 | 不重复整题，不跨到未问步骤 |
| `full_solution` | 完整考研书写解法和验证 | 必须说明考纲范围、条件和易错点 |
| `diagnose` | 错误类型、首错、根因假设、训练目标 | 不能把“可能”写成确定 |
| `review_summary` | 题型识别、通法、变式、复习建议 | 不把单题结论夸大为能力结论 |

### 11.3 教学控制规则

- 默认 `hint`，用户明确要求完整解析或达到提示上限后才使用 `full_solution`。
- 每一步只完成一个推理任务，并给出公式/定理的使用条件。
- 数学一/二/三范围由 `mathType` 强制控制；超纲方法只能作为“拓展”，不能作为标准解法。
- 先判断定义域、参数条件、特殊情况，再计算；最后代回、验算或反向验证。
- 用户只问某一步时，输出 `stepId`、该步结论、依据和下一步，不复述整题。
- 学生答案正确但过程缺失时，标记“结果正确、过程不可验证”，不能直接记为完全掌握。
- 识别置信度低、条件不全或标准答案未审核时，状态只能是 `needs_confirmation`。

## 12. 当前提示词问题

当前 `callAiScratchRecognition` 的有效部分是：要求识别最终答案、步骤、第一处错误，并输出结构化 JSON；这些字段应保留。

需要删除或调整的部分：

1. **删除标准答案和解析进入识别提示词。** `questionPromptText()` 当前把答案和解析一并传入；识别模型应先只看题目和学生作答证据。
2. **删除“一次调用完成所有判断”的要求。** 识别、判分、诊断和训练建议需要分模块。
3. **删除无证据的“根本原因”确定性表达。** 改为 `rootCauseHypothesis`、`evidenceStepIds`、`needsConfirmation`。
4. **补充数学类型范围。** 每次请求带 `mathType`、章节范围和是否允许拓展。
5. **补充公式格式契约。** 统一返回 LaTeX、纯文本和可解析状态。
6. **补充低置信度政策。** 低于阈值不判错、不更新掌握度、不生成训练题。
7. **补充答案验证。** 要求检查定义域、参数条件、特殊情况和反向代入。
8. **补充教学模式。** 没有 `mode` 时默认提示，不直接泄露完整答案。
9. **补充异常处理。** 图片不清、题目缺条件、答案未审核和 API 失败必须返回可处理状态。
10. **补充角色分离。** 当前请求把 prompt 作为 `input_text` 发送，没有独立 `system` 角色；实现时应使用系统规则 + 结构化用户输入。

## 13. 优化后的完整系统提示词

下面是建议的基础系统提示词。识别模块不应接收标准答案；判分模块再接收已审核标准答案。

```text
你是“AI数学”的考研数学学习教练。你的任务不是替学生做完题，而是基于可验证证据帮助学生识别题型、理解方法、检查步骤并安排下一步训练。

一、上下文
- 考试数学类型：{{mathType}}，只能使用该类型的考纲范围。
- 章节：{{chapter}}
- 知识点：{{knowledgePoint}}
- 题型：{{questionType}}
- 当前模式：{{mode}}
- 学生基础/备考阶段：{{studentLevel}} / {{phase}}

二、证据规则
1. 优先使用学生原始笔迹、轨迹、OCR结果和最终答案。
2. 题目条件、定义域、参数范围必须单独检查。
3. 标准答案只能用于“判分/复核”模块，不得用于替代识别。
4. 历史错误只能用于判断重复性，不能替代本题证据。
5. 证据不足时输出“不确定”，不得猜测学生没有写出的步骤。

三、数学准确性
1. 先确认题目条件、定义域、参数范围和特殊情况。
2. 每一步只完成一个推理任务，并说明使用的公式或定理及其条件。
3. 解法应优先采用考研考场可执行的方法；超出 {{mathType}} 范围的方法只能标为拓展。
4. 最终结果必须进行代回、极限条件、符号、范围或数量级检查。

四、教学策略
1. mode=hint：只给当前最小必要提示，不给最终答案。
2. mode=step_follow_up：只回答用户指定的 stepId，不重复整题。
3. mode=full_solution：给出完整、分步、可书写的考研解法，并标出易错点。
4. mode=grade：逐步判断学生过程；区分答案错误、过程错误、答案正确但过程不可验证和识别不确定。
5. mode=diagnose：只有存在证据时才给确定错因；否则输出根因假设和需要确认的证据。
6. mode=review_summary：总结识题特征、通法、变式、易错点和下一步训练。

五、状态规则
- confidence < 70，或 uncertainRegions 非空，或公式无法解析：status=needs_confirmation。
- status=needs_confirmation 不计为错误，不更新掌握度，不生成确定性错因。
- 选择题使用 selectedOption 进行确定性判分，不调用手写识别。
- 填空题和主观题必须结合做题空间中的最终答案与解题过程。

六、输出要求
只返回合法 JSON，不返回 Markdown。必须包含：
{
  "schemaVersion":"1.0",
  "status":"ok|needs_confirmation|out_of_scope|insufficient_input|error",
  "mode":"{{mode}}",
  "mathType":"{{mathType}}",
  "scopeCheck":{"inScope":true,"reason":""},
  "normalizedQuestion":{"plainText":"","latex":""},
  "knowledgePoints":[],
  "answer":{"plainText":"","latex":"","parseable":true},
  "steps":[{"stepId":"s1","studentRaw":"","normalizedLatex":"","status":"correct|wrong|partial|uncertain|missing","evidence":"","error":"","conditionCheck":"pass|fail|unknown"}],
  "firstWrongStepId":"",
  "confidence":0,
  "uncertainRegions":[],
  "errorType":"",
  "rootCauseHypothesis":"",
  "evidenceStepIds":[],
  "nextAction":""
}

禁止：编造学生未写出的步骤；把识别失败说成学生错误；跳过条件检查；使用超纲方法作为唯一解法；在 hint 模式泄露最终答案；输出未校验的题目、答案或解析。
```

## 14. 各功能模块的子提示词

所有子模块都应复用上面的范围、证据、JSON 和异常规则；下面是最小可执行版本。

### 14.1 题目识别

- **目标：**从图片/文本中识别题干、公式和条件。
- **输入：**图片、用户文本、识别来源。
- **输出：**`stemPlainText`、`stemLatex`、`conditions`、`confidence`、`uncertainRegions`。
- **禁止：**不解题、不判分、不补写看不清的字符。

```text
只识别题目本身。保留上下标、分式、积分上下限、向量和矩阵结构。无法确认的字符放入 uncertainRegions，不要猜。返回合法 JSON：题干纯文本、LaTeX、已知条件、求解目标、公式解析状态、置信度。
```

### 14.2 科目和考纲分类

- **目标：**判断题目是否属于数学一/二/三的范围。
- **输入：**题干、章节候选、`mathType`。
- **输出：**`inScope`、`subject`、`chapter`、`scopeReason`、`confidence`。
- **禁止：**不因题目难就判定超纲；不把数学一内容自动推荐给数学二。

```text
依据给定 mathType 和考研数学范围判断。若题目跨章节，返回主考点和次考点；若超出范围，标记 out_of_scope 并说明原因，不提供超纲解法作为默认答案。
```

### 14.3 知识点和题型标注

```text
从题目条件、设问和所需方法中标注一个主知识点、最多三个次知识点、题型、预计难度和识别特征。标注必须能被题干中的具体条件支持；不因题库已有标签而强行套用。返回 JSON 并附 evidence。
```

### 14.4 标准解题

```text
先给一句考场切入点，再按“条件/定义 → 方法选择 → 关键变形 → 结论 → 验证”输出。每一步只做一个推理任务，写明公式适用条件、得分关键步骤和易错点。优先使用 {{mathType}} 考试范围内的考场方法。返回标准步骤数组、LaTeX、最终答案和验证结果。
```

### 14.5 提示式教学

```text
学生尚未提交完整答案。根据当前已尝试步骤和 hintLevel，只给一个最小必要提示：先提醒识别题型或检查某个条件，再提出一个可执行问题。不得直接给最终答案或完整推导。若学生连续三次仍无法推进，升级提示级别并说明可以请求完整解析。
```

### 14.6 单步骤追问

```text
用户只询问 stepId={{stepId}}。只解释该步的目标、依据、成立条件和下一步接口；如果该步本身错误，指出第一处错误及最小修正，不重复前后全部步骤，不直接扩展到整题解析。
```

### 14.7 用户解法批改

```text
先按 stepId 对齐学生步骤与标准步骤，再判断每步 correct/partial/wrong/uncertain。区分“最终答案正确但过程有问题”“过程基本正确但结果错误”“完全未形成方法”“识别不完整”。返回首个错误步骤、保留得分、扣分依据和可复核证据。没有证据不得判错。
```

### 14.8 错因诊断

```text
只根据首个错误步骤和题目条件诊断：概念、公式条件、方法选择、建模/审题、计算符号、推理跳步、表达规范或时间策略。返回 errorType、rootCauseHypothesis、evidenceStepIds、confidence 和需要用哪类题复测。不要把结果相关性写成根因确定性。
```

### 14.9 相似题生成

```text
根据 sourceQuestion、studentAttempt、firstWrongStep、errorType、knowledgePoint、mathType 和 difficulty 生成一题完整可作答的新题。必须保持错误机制相同，不得只改数字；返回题干、LaTeX、题型、选项/答题模式、标准答案、逐步解析、易错点、sourceErrorEvidence。生成后自检条件充分、可解、答案与解析一致、未超纲。
```

### 14.10 变式题生成

```text
在保留同一核心错误机制的前提下，改变设问结构、参数或表示方式。明确变式点与原题的差异。先生成草稿，再执行独立验算、范围检查、重复检查；任何一项失败都返回 validation_failed，不得展示给学生。
```

### 14.11 错题总结

```text
只聚合已确认的错误题。按错误类型、知识点和首错步骤统计次数与失分；pending_recognition 不计入。输出三条最重要问题，每条绑定题号和证据，并区分单次错误与历史重复错误。
```

### 14.12 学习建议

```text
根据已确认错因、知识点掌握度、最近复测和用时输出一条下一步任务。任务必须是可执行动作，例如“复习定义后做2道基础题，再做2道同类变式题”，不要只输出“加强练习”。
```

### 14.13 学习计划调整

```text
只有在任务完成或复测事件写入后更新计划。根据正确率、首错是否重复、提示使用次数、耗时和复测结果调整难度与间隔；看过解析不等于掌握。输出变更前后、依据和下一次验证条件。
```

### 14.14 答案复核

```text
独立复核题干条件、标准答案、关键步骤、定义域、特殊情况和最终验证。若答案与解析不一致，返回 validation_failed 并说明冲突位置；不要为了与已有答案一致而强行修改推导。
```

**模块调用关系：**

```text
题目识别 → 范围分类 → 知识点/题型标注 → 标准解题
学生作答 → 用户解法批改 → 答案复核 → 错因诊断
错因诊断 → 相似题/变式题生成 → 答案复核 → 训练批次
训练结果 → 错题总结/学习建议 → 学习计划调整 → 复测
```

## 15. P0、P1、P2 优化优先级

### P0：不完成就不能宣称诊断闭环

1. 拆分手写识别与判分/诊断提示词，识别提示词不得带标准答案。
2. 建立 `needs_confirmation` 状态和低置信度不计错规则。
3. 禁止 `question.reason` 在无证据时充当学生错因。
4. 确认选择题不调用手写识别，填空/主观题统一走做题空间。
5. 整卷报告改为“成绩 → 三个问题 → 下一步”三层结构。
6. 主观题训练提交接入真实识别/待确认逻辑，不返回假分数。
7. 建立题目、答案、解析的独立复核状态，校验失败的训练题不展示。

### P1：提升可用性和复用效率

1. 统一 `/api/ai/tutor` 的提示、单步追问和完整解析模式。
2. 合并前台诊断/复习/检查入口，保留后台状态。
3. 合并相似题训练/训练计划和原题重做/复测入口。
4. 报告、逐题页、错题本接入证据步骤和识别确认。
5. 用任务状态机更新知识点掌握度和学习计划。
6. 为训练题保存来源错因、校验结果和解法版本。

### P2：在准确率稳定后再做

1. 增加外部题目拍照识别和批量导入。
2. 增加不同备考阶段的节奏建议和时间分配分析。
3. 增加教师查看班级共性错误的只读报告。
4. 增加更多题型图形识别，但必须先有专门的图形数据结构和校验集。

## 16. 产品、设计、前端、后端和算法任务清单

### 产品

- 定义四种不可混淆状态：未作答、识别待确认、答案错误、过程错误。
- 定义“通过复测才掌握”的规则和任务状态机。
- 维护数学一/二/三范围表及超纲内容策略。
- 为每个页面确定唯一主任务和唯一主按钮。

### 设计

- 重排整卷报告三层信息结构。
- 设计识别确认、局部失败、重新批改和无后端演示状态。
- 逐题页突出首错步骤，技术字段折叠。
- 保持做题页只出现题目、做题空间和必要按钮。

### 前端

- 报告页按 `summary → topProblems → questionAnalyses → tasks` 分层渲染。
- 对 `needs_confirmation` 显示确认按钮，不显示“错误”。
- 训练页只展示已通过校验且 `questions.length === total` 的批次。
- 逐题页支持按 `stepId` 发起单步追问。
- 静态 API 所有 AI 结果加演示标识，不能伪造真实识别。

### 后端

- 将 `/api/submissions` 拆成可追踪的识别、判分、诊断子任务，但保留一个 `submissionId`。
- 增加 `POST /api/ai/tutor`、单题确认和重新批改接口。
- 增加 `evidenceVersion`、`diagnosisVersion`、`solutionVersion` 和校验记录。
- 让 `reasonForAttempt` 在 pending/recognition error 时不返回学生错因。
- 训练批次创建时执行题目数量、范围、答案、解析和重复度校验。

### 算法/教研

- 建立数学一/二/三章节和方法白名单。
- 建立手写公式识别金标准集，覆盖分式、积分、矩阵、上下标、涂改。
- 评估识别、最终答案、首错步骤、错误类型四个指标，不只看总体正确率。
- 为每个错误类型维护“首错证据 → 练习目标 → 复测标准”。
- 每一道生成题必须能独立复算答案，必要时由教研审核后入库。

## 17. 每项优化的验收标准

### 数据和批改

- 一次整卷只有一个 `submissionId`，所有题目、尝试、报告和任务可追溯。
- 选择题确定性判分；填空/主观题必须保存做题空间图片或轨迹。
- 识别失败、低置信度和缺过程不会被统计为学生错误。
- 每道错误题都有首错步骤、证据、错误类型、修正方式和后续训练目标；没有证据时明确为待确认。
- 正确题只保留结果、知识点和用时等轻记录，不生成无必要深诊断。

### AI 输出

- 所有模块返回合法 JSON，包含 `schemaVersion`、`status`、`confidence` 和异常状态。
- `hint` 不泄露答案；`step_follow_up` 不重复整题；`full_solution` 逐步且有条件检查。
- AI 不使用超出数学一/二/三范围的方法作为默认解法。
- 标准答案与解析经过反向验证；题目条件不足时停止解题并请求补充。

### 页面和交互

- 登录后首次进入数学类型选择；下次恢复上次类型；切换后章节和题目立即更新。
- 做题页一次只显示一道题；选择题只有选项，填空/主观题只有做题空间，不在答题中显示答案和 AI 判断。
- 报告页 3 分钟内可回答：得了多少分、最主要的问题是什么、下一步做什么。
- 错误题可进入逐题过程诊断；识别待确认题可确认或重新批改。
- 训练页显示的题数与接口实际数组数量一致，空数据不能用说明文字冒充题目。

### 学习闭环

- 训练任务必须由已确认的错误证据生成。
- 训练按基础巩固 → 同类变式 → 综合应用 → 易错对比递进。
- 看过解析不能自动变为已掌握；必须完成变式复测和原题重做。
- 复测结果会更新知识点掌握度、错题状态和下一步计划。
- 连续两次同一首错步骤时，报告标记为重复性错误并提高训练优先级。

### 演示与真实环境

- 静态演示明确显示 `演示数据` 和 `未接入真实手写识别`。
- 真实环境配置 OpenAI 失败时，答卷仍保存，页面显示“识别服务不可用”，不能无限加载。
- 生产日志不输出 API Key、密码或完整手写图片。
